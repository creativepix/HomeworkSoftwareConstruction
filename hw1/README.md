# ВышКат

Консольное приложение на C# для учёта парка кикшеринга. Оно принимает транспорт после техосмотра, хранит транспорт и вещи на балансе, считает суточное энергопотребление и показывает технику, подходящую новичкам.

## Структура

- `Vyshkat.Domain` — доменная модель и правила учёта;
- `Vyshkat.ConsoleApp` — консольное меню и настройка DI-контейнера;
- `Vyshkat.Tests` — поведенческие тесты доменной логики.

Основные абстракции разделены по назначению: [`IInventoryItem`](Vyshkat.Domain/Interfaces/IInventoryItem.cs) описывает объект с инвентарным номером, [`IEnergyConsumer`](Vyshkat.Domain/Interfaces/IEnergyConsumer.cs) — потребителя энергии, [`IEasyToUse`](Vyshkat.Domain/Interfaces/IEasyToUse.cs) — оценку простоты, а [`ITransport`](Vyshkat.Domain/Interfaces/ITransport.cs) объединяет свойства прокатной техники. Поэтому, например, велосипед не обязан иметь расход энергии, а зарядный шкаф может участвовать в отчёте об энергии, не являясь транспортом.

[`Park`](Vyshkat.Domain/Services/Park.cs) хранит принятые объекты и формирует отчёты. Перед добавлением он запускает набор `IInventoryChecker`: [`InventoryNumberChecker`](Vyshkat.Domain/Services/InventoryNumberChecker.cs) не допускает повторения инвентарных номеров, [`EasyLevelChecker`](Vyshkat.Domain/Services/EasyLevelChecker.cs) проверяет простоту 1-10, а [`EnergyChecker`](Vyshkat.Domain/Services/EnergyChecker.cs) не допускает отрицательный расход энергии. [`ServiceCenter`](Vyshkat.Domain/Services/ServiceCenter.cs) отдельно проводит техосмотр транспорта.

## Соответствие ТЗ

| Требование | Реализация и комментарий |
|---|---|
| Добавление транспорта | В меню доступны самокат, велосипед и электровелосипед. `Park.AddTransport` возвращает явный результат добавления. |
| Техосмотр перед приёмкой | `Park` вызывает `IServiceCenter.CanAccept`. Транспорт с энергопотреблением проходит проверку только при расходе больше нуля; обычный велосипед принимается без проверки батареи. |
| Отчёт по парку | `TotalItemsCount` считает весь баланс, а `TotalEnergyPerDay` суммирует расход всех объектов с интерфейсом `IEnergyConsumer`, включая зарядные шкафы. |
| Техника для новичков | В [`Transport`](Vyshkat.Domain/Models/Transport.cs) зафиксировано правило из ТЗ: `EasyLevel >= 6`. |
| Учёт вещей | Шлемы, док-станции и зарядные шкафы наследуются от `InventoryItem`; `AllItems` выводит их вместе с транспортом. |
| Демонстрация сценариев | [`Program.cs`](Vyshkat.ConsoleApp/Program.cs) позволяет добавить транспорт или вещь, получить оба отчёта и увидеть все номера. Отказ техосмотра можно проверить, введя нулевой расход энергии; повтор номера показывает отдельную ошибку. |

## SOLID и DI

- **S — Single Responsibility.** `ServiceCenter` отвечает за техосмотр, `InventoryNumberChecker` — за уникальность номера, `EasyLevelChecker` и `EnergyChecker` — за простые проверки вводимых значений, модели — за собственные данные, `Park` — за операции над парком.
- **O — Open/Closed.** Новый класс транспорта можно реализовать через `ITransport`, а при необходимости `IEnergyConsumer`; отчёты `Park` менять не потребуется. Принцип сознательно ограничен в консольном интерфейсе: новый тип нужно добавить в меню `Program.cs`. Для небольшого учебного приложения это проще и понятнее, чем отдельная фабрика и система регистрации команд.
- **L — Liskov Substitution.** `Scooter`, `Bicycle` и `ElectricBicycle` используются в `Park` через `ITransport` без проверки их конкретного типа.
- **I — Interface Segregation.** Инвентаризация, энергопотребление и простота разделены на небольшие интерфейсы; классы реализуют только нужные возможности.
- **D — Dependency Inversion.** Наиболее явно применён этот принцип: `Park` зависит от `IServiceCenter` и набора `IInventoryChecker`, а не от конкретных реализаций. Зависимости передаются через конструктор и настраиваются в DI-контейнере.

DI-контейнер настраивается в [`Program.cs`](Vyshkat.ConsoleApp/Program.cs): в нём регистрируются техосмотр, проверки и сам парк. Доменный проект при этом не зависит от библиотеки контейнера.

## Расширение программы

При добавлении нового вида транспорта доменная логика и отчёты не сломаются: достаточно реализовать `ITransport` или унаследоваться от `Transport`. Для электрической модели дополнительно реализуется `IEnergyConsumer`. Изменить потребуется только создание объекта в консольном меню.

Сотрудник не должен реализовывать `IInventoryItem`, поскольку по ТЗ сотрудники не ставятся на баланс. Для их учёта понадобится отдельная модель и сервис, но существующий парк менять не обязательно. Запчасть можно добавить как наследника `InventoryItem`; полноценный склад лучше оформить отдельным сервисом, чтобы `Park` не получал вторую ответственность.

## Тесты

В [`ParkTests`](Vyshkat.Tests/ParkTests.cs) проверяются приём и отклонение транспорта, сумма энергии, уникальность номеров, общий список имущества и граница правила для новичков. В тестах используется `FakeServiceCenter`: он реализует `IServiceCenter` и возвращает заранее заданное решение. Так зависимость подменяется через конструктор без настоящего техосмотра и без привязки к DI-контейнеру.

На текущей версии проходят все 8 тестов. Покрытие по `dotnet test --collect:"XPlat Code Coverage"`: строки — 84,56%, ветки — 90,90%.

## Запуск

Требуется .NET SDK 10.

```bash
dotnet run --project Vyshkat.ConsoleApp
```

Запуск тестов:

```bash
dotnet test
```

Запуск команд предполагается из каталога `hw1`.
