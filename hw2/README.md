# ПОС: преподавательская оценка студентов

Консольное приложение на C#/.NET 10 для ведения студентов, рубрикатора и оценок. Данные хранятся в JSON, итоги экспортируются в CSV.

## Возможности

- добавить студента и посмотреть список студентов;
- добавить критерий с максимальным баллом и весом;
- выставить, посмотреть, исправить или отменить оценку;
- вычислить итог студента по текущему рубрикатору;
- экспортировать итоги всех студентов в CSV;
- продолжить работу после ожидаемой ошибки ввода или доступа к файлу.

## Предметная логика

Домен использует следующие правила:

- имя студента и название критерия не могут быть пустыми;
- максимальный балл и вес критерия должны быть больше нуля;
- балл находится в диапазоне от `0` до максимума критерия включительно;
- оценку можно создать только по критерию из текущего рубрикатора;
- в рубрикаторе нельзя повторить идентификатор или название критерия;
- у пары «студент + критерий» хранится одна текущая оценка; повторное выставление заменяет её;
- итог не хранится отдельным числом, а каждый раз вычисляется из рубрикатора и текущих оценок.

Формула итога:

```text
sum((score / maxScore) * weight) / sum(weights) * 10
```

Критерий без оценки даёт вклад `0`. Для пустого рубрикатора итог равен `0`. Результат находится в диапазоне от `0` до `10`.

## DDD

### Entity

Entity имеет идентичность, которая сохраняется независимо от остальных полей. В проекте entities представлены классами `Student`, `Criterion` и `Evaluation`.

```csharp
var studentId = new StudentId(Guid.NewGuid());
var student = new Student(studentId, "Иван Иванов");
```

Два студента с одинаковым именем и разными `StudentId` технически являются разными entities. При этом прикладной сценарий дополнительно запрещает повтор имени.

`Evaluation` тоже является entity: у неё есть `EvaluationId`, студент, критерий, балл, дата и необязательный комментарий.

### Value object

Value object определяется значением, а не собственной изменяемой идентичностью.

Идентификаторы оформлены как неизменяемые value objects:

```csharp
public readonly record struct StudentId(Guid Value);
public readonly record struct CriterionId(Guid Value);
```

`Score` хранит проверенный балл:

```csharp
var score = new Score(8m, 10m);
```

Конструктор `Score` отклонит значение меньше `0` или больше `10`. Поэтому недопустимый балл нельзя протащить в `Evaluation` через консоль или загрузку JSON.

### Aggregate и domain service

`Rubric` является aggregate: он владеет коллекцией критериев и проверяет её целостность. Добавление критерия проходит через `Rubric.AddCriterion`.

`WeightedFinalScoreStrategy` является domain service. Расчёт итога не принадлежит одной оценке или одному критерию, потому что использует весь рубрикатор и набор оценок студента.

Repository ports находятся в Domain:

- `IStudentRepository`;
- `IRubricRepository`;
- `IEvaluationRepository`.

Домен описывает нужные операции, но не знает, что данные лежат в JSON.

## Архитектура и зависимости

Проект использует учебную Clean Architecture.

```text
Pos.Console ---------> Pos.Application ---------> Pos.Domain
     |                       ^
     |                       |
     +-----> Pos.Infrastructure ---------------> Pos.Domain

Pos.Tests -----------> все проверяемые проекты
```

Направления зависимостей:

- `Pos.Domain` ни от кого не зависит;
- `Pos.Application` зависит от `Pos.Domain`;
- `Pos.Infrastructure` зависит от `Pos.Application` и `Pos.Domain`;
- `Pos.Console` зависит от `Pos.Application` и `Pos.Infrastructure`;
- `Pos.Tests` проверяет Domain, Application, Infrastructure и Console.

`Program.cs` является composition root. Он создаёт DI-контейнер, связывает один экземпляр `JsonPosRepository` с тремя repository ports, получает `ConsoleApp` и запускает его. Сценариев и расчётов в `Program.cs` нет. Ожидаемые ошибки начальной загрузки JSON выводятся без необработанного исключения.

## Паттерны и архитектурные механизмы

| Паттерн | Где | Какую проблему решает и почему выбран |
|---|---|---|
| Factory | `EvaluationFactory` | Не даёт создать оценку по неизвестному критерию и всегда создаёт `Score` с максимумом нужного критерия. Проверка не размазана по консоли, фасаду и JSON-загрузке. |
| Strategy | `IFinalScoreStrategy`, `WeightedFinalScoreStrategy` | Отделяет правило итогового расчёта от фасада и entities. Фасад зависит от контракта расчёта, а сама формула остаётся доменным сервисом. |
| Facade | `IPosFacade`, `PosFacade` | Консоли не нужно координировать три репозитория, фабрику и стратегию. Она вызывает одну прикладную точку и получает DTO, а не доменные объекты. |
| Repository | три интерфейса в Domain | Домен и Application работают с хранением через контракты. Формат JSON можно заменить без переноса файловой логики в домен. |
| Infrastructure adapters | `JsonPosRepository`, `CsvResultExporter` | Реализуют repository/export ports через конкретные JSON- и CSV-файлы. Файловые API остаются в Infrastructure. |
| Dependency Injection | `Program.cs` | В одном месте связывает интерфейсы и реализации. В тестах реальные зависимости можно заменить fake-объектами или текстовыми потоками. |

В текущей версии используются три GoF-паттерна: Factory, Strategy и Facade. Repository относится к DDD. Dependency Injection и infrastructure adapters описывают устройство слоёв, но не выдаются здесь за дополнительные GoF-паттерны.

## Хранение и восстановление

Рабочий JSON создаётся по пути:

```text
Pos.Console/bin/Debug/net10.0/data/pos-data.json
```

Путь считается от каталога собранного приложения. После каждого успешного изменения репозиторий полностью переписывает JSON. Сначала запись должна завершиться успешно, и только после этого новое состояние фиксируется в памяти.

При загрузке JSON данные восстанавливаются через доменные конструкторы, `Rubric.AddCriterion` и `EvaluationFactory`. Поэтому ручное добавление недопустимого балла или неизвестного критерия в файл не обходит инварианты.

CSV создаётся по пути, который пользователь вводит в меню. Экспортёр создаёт отсутствующие каталоги и экранирует запятые, кавычки и переводы строк.

## Пример работы

1. Выбрать `1`, ввести имя студента.
2. Выбрать `3` два раза и добавить критерии, например:
   - `Архитектура`, максимум `10`, вес `1`;
   - `Тесты`, максимум `20`, вес `3`.
3. Выбрать `2` и `4`, чтобы получить идентификаторы студента и критериев.
4. Выбрать `5` и выставить две оценки.
5. Выбрать `8`, вставить `StudentId` и получить итог по шкале `0..10`.
6. Выбрать `9` и указать путь, например `exports/results.csv`.
7. Выбрать `0` для выхода.

Повтор команды `5` для той же пары студент-критерий исправляет текущую оценку. Команда `7` отменяет её.

## Ограничения

- Приложение рассчитано на локальную однопользовательскую работу.
- Одновременная запись из нескольких процессов не поддерживается.
- JSON переписывается целиком; атомарной замены и восстановления повреждённого файла нет.
- Студентов и критерии можно добавлять и просматривать, но нельзя переименовывать или удалять через текущее меню.
- Идентификаторы имеют формат GUID, поэтому в консольных командах их нужно копировать из списков.
- CSV поддерживает только экспорт итогов; обратного импорта нет.
- При повреждённом JSON рабочее меню не запускается, потому что домен отклоняет некорректное состояние. Программа выводит понятную ошибку запуска и завершается без необработанного исключения.
